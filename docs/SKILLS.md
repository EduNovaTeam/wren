# Skill

Skill 是「一类事该怎么做」的说明书：一段 Markdown 正文，加上可选的附属资料和它需要的工具。
模型按需启用，启用后在本会话里持续生效；不用的时候只出现在系统提示的简介目录里，不占正文的上下文。

## 来源与覆盖

| 来源 | 位置 | 说明 |
|---|---|---|
| 内置 | 仓库的 `skills/` | 随代码分发 |
| 用户 | `WREN_SKILLS_DIR`，默认 `<数据目录>/skills` | 本地文件，不入库，可以随时改 |

两个目录都按「一个子目录一个 Skill」扫描。同名时以用户目录为准；**用户版本存在但无效时不会回退到内置版本**，设置页会直接显示它的错误。

```
skills/
└── weekly-report/
    ├── SKILL.md
    ├── references/
    │   └── template.md
    └── assets/
        └── example.md
```

扫描时只解析元数据和正文，不读取附件，也不会把正文注入模型；正文和附件在激活 / 调用工具时才读取。
一次模型请求内使用同一份扫描快照，正文和工具权限不会来自不同版本的文件。

## SKILL.md 格式

```markdown
---
name: weekly-report
description: 用户需要写周报、周总结时使用。
allowed-tools: current_time
---

先读取 references/template.md。
根据用户提供的工作内容撰写周报。
```

支持的前置信息（frontmatter）是 YAML 的一个严格子集：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 小写字母、数字和短横线，必须与目录名一致 |
| `description` | 是 | 一句话简介，最多 1024 字；用于目录 |
| `allowed-tools` | 否 | 需要的工具，空格或逗号分隔；也可以写成缩进 2 格、每行 `- 工具名` 的列表 |
| `license` | 否 | 字符串 |
| `compatibility` | 否 | 字符串 |
| `metadata` | 否 | 一层缩进的 `键: 值`，值均为字符串 |

取值写成一行 `键: 值`，可以用单引号或双引号包裹。**不支持**的写法会直接报错，而不是猜一个结果：
多行值（`|`、`>`）、流式集合（`[...]`、`{...}`）、锚点 / 别名 / 标签、注释、制表符、未知字段、重复字段。

`allowed-tools` 是对已注册工具的引用，不是执行任意代码的授权。声明了未注册的工具时，该 Skill 显示为不可用并拒绝激活，例如示例中的 `metrics-query` 依赖一个不存在的 `run_sql`；这不影响其他 Skill。

## 激活

两种方式：

- 用户在消息开头输入 `/weekly-report 帮我整理这周的工作`。只识别消息开头，正文里的 `/xxx` 不当作命令；程序在第一次模型请求前完成校验和激活，用户消息原样保留在历史里。
- 模型调用 `activate_skill(name)`。它和 `/命令` 走同一套校验，重复激活是幂等的。

激活会：校验 Skill 存在、有效、已启用 → 读取正文并检查正文预算 → 把激活状态保存到后端 → 返回正文。
激活后，当前会话后续每次模型请求都会携带正文（包括同一回合里工具执行后的再次请求）。因此历史被截断也不影响已激活的 Skill。
同一份正文不会在一个请求里出现两次：如果激活回合还在历史中，正文已经由那条工具结果承载，系统提示就不再重复注入；只有激活回合被历史预算丢掉时，才从系统提示补回。

激活状态保存在后端，可以刷新页面、重启进程；刷新后聊天界面会从后端恢复「已启用 Skill」列表。
用户可以随时从会话里移除，或在设置页全局停用；下一次模型请求起就不再注入正文、不再开放工具。历史里已经产生的文字不会被删除。

## 附属资源

`activate_skill` 只加载 `SKILL.md`，不递归读取附件。正文提到模板或参考资料时，模型调用：

```json
{ "name": "weekly-report", "path": "references/template.md" }
```

`read_skill_resource` 只允许读取**当前会话已激活、仍有效且启用**的 Skill 的资源；结果作为普通工具消息参与后续请求，受历史预算限制，不永久注入系统提示。
第一版只返回文本文件，二进制会明确报错；超出返回上限时会提示截断和总长度。

## 工具权限

| 工具类型 | 什么时候可以给模型 |
|---|---|
| 普通工具（如 `current_time`） | 按设置页的开关，默认开启 |
| 按需工具（如 `fetch_url`） | 至少一个已激活 Skill 的 `allowed-tools` 声明了它，且用户没有明确关闭 |
| 用户明确关闭的工具 | 任何 Skill 都不能重新打开 |
| 未注册的工具 | 不可调用；依赖它的 Skill 显示为不可用 |

`activate_skill` / `read_skill_resource` 是框架工具，始终可用，但只操作 Skill，不直接提供外部能力。
工具列表在**每次模型请求前**重新计算：激活成功后从下一次请求起开放新工具；同一个模型响应里夹带的其他工具调用不会因为刚完成的激活而获得新权限。每个调用执行前都会再读一次状态并与请求时的集合取交集，因此用户中途关闭工具或停用 Skill、甚至同一响应里前一个调用改变了权限，都会立即撤销后续调用。状态读取失败时拒绝执行并返回明确错误，不沿用旧权限。

## 上下文预算

Skill 的正文和目录有独立预算（按估算 token，可在 `.env` 里调整），不占用「设置 → 模型 → 历史预算」：

| 预算 | 默认 | 环境变量 |
|---|---|---|
| 单个 Skill 正文 | 24000 | `WREN_SKILL_BODY_BUDGET` |
| 简介目录 | 1500 | `WREN_SKILL_INDEX_BUDGET` |
| 同时激活的正文总和 | 40000 | `WREN_SKILL_ACTIVE_BUDGET` |

正文超限时**明确拒绝激活**，不做静默截断；目录超预算时截断简介并注明还有几个未列出。恢复已有激活状态和刷新状态时同样检查总预算：超出总预算的 Skill 不会加载正文或开放工具，并发出「不可用」事件，需要先移除其他 Skill 或调高预算。
内置的 `error-code-lookup` 正文约 2.2 万 token，默认上限是按它定的；觉得上下文太贵可以调低，代价是这个 Skill 会显示为不可用。

## 文件安全

所有正文和资源读取都经过 `agent/src/skills/read.js`：

- 只接受 Skill 目录内的相对路径，拒绝绝对路径、`.`、`..`、反斜杠和 NUL；
- 用真实路径（`realpath`）检查，阻止符号链接把读取带出 Skill 目录；
- 只读普通文件；单文件上限 128 KB，一次返回最多 12000 字符；
- 只支持 UTF-8 文本，二进制内容直接报错；
- 错误只说明原因，不返回目录外的任何内容。

Skill 不能修改系统权限，也不能绕过用户在设置页做的明确限制。

## 第一版不做

- 不执行 Skill 自带的脚本。
- 不提供在线安装 / 市场。
- 附件只读文本；不支持图片、PDF 等。
- 同一个回合内，正文和工具权限来自回合开始时的快照，附件在读取时即时校验；Skill 文件在回合中途被改动，可能读到新附件，但正文和权限仍是旧快照。
