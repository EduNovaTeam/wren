# Skill 系统的实现与验证

## 从一次使用理解

用户输入 `/weekly-report 本周完成了原型` 时，原消息仍完整落库。Agent 先请求后端激活
`weekly-report`，把去掉命令的用户消息和该技能正文交给模型。模型需要模板时再调用
`read_skill_resource`。用户下一条说「再精简一点」，后端会把会话中的已激活技能重新交给
Agent，不依赖先前消息是否还在历史预算内。

不使用斜杠时，模型先看到有效、启用技能的名称与简介，通过 `load_skill` 选择相关技能。
未选中技能的正文和资源不会预先加入上下文。

## 各层怎样分工

| 位置 | 职责 |
| --- | --- |
| `backend/wren/skills.py` | 发现两种来源、校验 YAML、安全读取文本 |
| `backend/wren/skill_state.py` | 技能开关、会话激活记录、每回合重新加载 |
| `backend/wren/api/skills_api.py` | 设置、会话移除、内部激活及资源接口 |
| `agent/src/skills.js` | 当前回合的技能、提示段和工具权限 |
| `agent/src/skill-discovery.js` | 只展示简介并提供 `load_skill` |
| `web/src/features/skills.js` | 设置路由、导航及激活事件卡片 |

后端仍是唯一持久化层。新增迁移 `003_skills.sql` 保存会话激活记录，工具开关单独使用
`settings` 表的 `skills` 键。Agent 的注册表与激活集合都是每回合的局部对象。

## 取舍

- 使用 Python 端 PyYAML 的安全加载器，避免用正则模拟 YAML；没有给 Agent 增加依赖。
  重复键、别名、复杂标签及错误类型会得到诊断。
- 只扫描来源根下的直接子目录。本地同名目录优先，即使无效也显示错误，不静默退回内置。
  本地目录默认是数据目录下的 `skills`，可用 `WREN_SKILLS_DIR` 指定。
- 系统提示中只有已激活技能的正文；待加载技能只有简介。资源不预读，调用工具时分页返回。
  单文件最多 256 KiB，能覆盖仓库约 70 KiB 的错误码示例。
- 默认工具沿用现有设置；`allowed-tools` 使用准确的注册名，为已激活技能开放按需工具。
  不能打开全局关闭的工具，也不会注册并不存在的 `run_sql`，没有通配符授权。
- 自动加载必须改变回合内后续请求的工具集合，因此调整了核心文件 `turn.js`。
  同一模型响应中的调用共享该步开始时的权限；技能刚加载成功时，同批的新增工具调用仍被拒绝，
  下一次模型请求才会看到新工具。这是对原先「全回合工具不变」约定的明确扩展。
- 正文在每个回合重新读取；激活记录独立于历史消息。停用技能会清除所有会话中的激活记录，
  重新启用不会自动恢复。停止一回合不会自动撤销已成功的激活。
- 内部激活和资料读取绑定运行中的 `turn_id`，从数据库确定所属会话，调用方不能指定另一会话。
  所有内部接口沿用共享口令。资源读取还检查该技能已激活且当前可用。

## 读取边界与范围

文件路径解析后必须留在选定技能目录内；技能目录本身必须留在来源根内。绝对路径、盘符、
反斜杠、上级目录、NTFS 备用数据流路径及逃逸的符号链接会被拒绝。
读取前检查普通文件和大小，并限制实际读取量；无效 UTF-8、循环链接等显示为错误。

这套检查面向本机单用户的外部技能文件，不提供对抗另一个本地进程在检查与打开间并发替换
文件系统目录的隔离保证。已发送给模型的内容也无法通过停用操作撤回；完整历史仍保留。

本期不执行技能脚本，不提供在线安装，不补做 SQL 工具。自动选用由模型根据简介决定，
并非关键词匹配或保证每次命中的分类器；需要确定选用时使用 `/技能名`。

同会话精简，以及新会话自动加载翻译技能并保留 Markdown 加粗。
这部分是实际模型的人工验收，与 fake LLM 自动测试分别记录。
